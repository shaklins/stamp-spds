# Шаблон текстовой части проектов по СПДС

Это шаблон текстовой части проектной документации, выполненной в соответствии с системой СПДС (Система проектной документации для строительства). Шаблон предназначен для быстрой сборки стандартных документов.

> [!WARNING]
> Пакет находится в разработке, функционал может измениться в любой момент.

## Структура проекта

Общая схема — в [struct.md](struct.md).

### Документы (корень проекта) — точки входа компиляции

| Файл | Назначение |
|---|---|
| `01-cover-title.typ` | Обложка и титульный лист проекта |
| `02-general-data.typ` | Общие данные (`ОД`) — основные указания, вставки ведомостей |
| `03-explanatory.typ` | Пояснительная записка (`ПЗ`) |
| `04-cable-journal.typ` | Кабельный журнал (`КЖ`) — форма 1 |
| `05-specification.typ` | Спецификация оборудования (`СО`) |

### Папка `sections/` — вставки и подразделы

| Файл | Назначение |
|---|---|
| `drawing-list.typ` | Ведомость рабочих чертежей основного комплекта (`ЭЧ`, `.ОД`, `.ПЗ`) |
| `reference-docs.typ` | Ведомость ссылочных и прилагаемых документов (`.КЖ`, `.СО`, ГОСТы) |

### Папка `data/` — табличные данные (CSV)

| Файл | Назначение |
|---|---|
| `drawing-list.csv` | Данные ведомости рабочих чертежей |
| `reference-docs.csv` | Данные ведомости ссылочных и прилагаемых документов |
| `cable-journal.csv` | Данные кабельного журнала |
| `equipment-spec.csv` | Данные спецификации оборудования |

Первая строка каждого CSV — заголовок, при выводе она пропускается.

### Папка `template/` — шаблоны оформления

| Файл | Назначение |
|---|---|
| `template.typ` | Основной шаблон страницы СПДС (формы 3, 4, 5, 6) |
| `frame.typ` | Рамка документа |
| `tables-spds.typ` | Таблицы форм СПДС |
| `tables-eskd.typ` | Таблицы форм ЕСКД |
| `place.typ` | Утилита размещения элементов |

### Папка `config/`

| Файл | Назначение |
|---|---|
| `data_stamp.typ` | Данные штампа (организация, авторы, шифр) |
| `logo.jpg` | Логотип для титульного листа |

## Компиляция

Все документы собираются в папку `pdf/`. Для сборки используется флаг `--root`, указывающий корень проекта:

```bash
typst compile --root . 02-general-data.typ pdf/02-general-data.pdf
```

### Сборка через make

Есть два мейкфайла. На Windows используется `mingw32-make` (или `make`, если он есть в PATH):

| Мейкфайл | Что делает | Результат |
|---|---|---|
| `Makefile` | Собирает каждый документ отдельно (объединённый файл не делает) | `pdf/01-cover-title.pdf` … `pdf/05-specification.pdf` |
| `Makefile.merged` | Собирает все документы и склеивает в один файл | `pdf/stamp-spds.pdf` (с закладками) |

```bash
# каждый документ отдельно
mingw32-make

# все документы в один PDF
mingw32-make -f Makefile.merged

# удалить папку pdf/ целиком
mingw32-make clean
mingw32-make -f Makefile.merged clean
```

Склейка выполняется скриптом `tools/merge_pdf.py` (пакет `pypdf`, добавляет закладки по документам):

```bash
python -m pip install pypdf
```

Повторная сборка пересобирает только то, что изменилось: правка любого файла в `template/`, `config/`, `sections/` или `data/` пересобирает все документы.

### Сборка без make

```powershell
New-Item pdf -ItemType Directory -Force | Out-Null
Get-ChildItem *.typ | ForEach-Object {
  typst compile --root . $_.FullName "pdf/$($_.BaseName).pdf"
}
```

Флаг `--root .` нужен для корректного разрешения путей (`#include`, `#import`, `csv(...)`, пути к изображениям): из корня пути идут как `template/...`, `config/...`, `data/...`, из `sections/` — как `../data/...`.
